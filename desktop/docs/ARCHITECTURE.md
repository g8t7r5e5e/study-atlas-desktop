# Desktop architecture and schema

Electron main owns SQLite (Node built-in `node:sqlite`), dialogs and files. The sandboxed renderer receives only a fixed preload API. All incoming snapshots undergo size, shape, date, number, identity and enum validation. Main checks top-frame sender URL. File access is restricted to paths chosen by native dialogs or app-owned data directories. Imports use an opaque preview token, not renderer-provided arbitrary paths.

The approved plain-JavaScript renderer remains the UI. Build-time handler compilation turns HTML event attributes and button action strings into lexical closures registered under opaque IDs; shipped code requires neither eval nor inline-script CSP. Event attributes containing imported record identifiers become closure values, not executable source. A data-only friend curriculum replaces the original owner seed. The owner may explicitly generate/import a private plan JSON outside packaged files.

SQLite schema 1 has records(category,id,ordinal,date,daily,body), a unique daily-date index, metadata and import receipts. JSON columns preserve all legacy extension fields; indexed stable identities and daily uniqueness enforce shared-record integrity. Array order remains available to the original UI; indexes are not identities. Schema 2 adds timestamped topic events and asset bytes. WAL + synchronous FULL and transactions commit every save. The bounded synchronous save IPC preserves the renderer's existing synchronous action semantics and prevents false success; failures throw before success messages or modal closure.

Profile image bytes are validated by type/signature, saved transactionally in SQLite, and materialized under userData/assets. Complete logical snapshots are read in one SQLite transaction and embed images; no live DB-file copy occurs. Backups use temp/write/fsync/rename. Restore validates before creating a safety backup, then replaces records and metadata in a single transaction. SQLite rollback/WAL recovery provides interrupted restore recovery. Seven daily automatic backups rotate; pre-import/pre-reset backups are retained. Closing checkpoints WAL.

Prototype imports support Settings `{version:1,exportedAt,demo}` and the localStorage `{demo,ui}` wrapper. Preview explains replacement and unresolved source IDs. Unknown legacy fields are retained; missing assessment/milestone categories use current seed defaults, while explicit empty arrays remain empty. Legacy blocks receive deterministic IDs; reimports use canonical content hashes and receipts. `topic` remains the latest authoritative overall status over older `edits`; checks only fill task status when no taskStates status exists. Source IDs remain intact for later owner-plan imports. The backup cannot recover base records absent from it: import an owner-plan JSON when the preview reports unresolved source references.

Runtime resources are local. The app uses `atlas://app/`, a restrictive CSP, no remote requests, contextIsolation, no Node integration, renderer sandbox, disabled webviews and denied permissions. Only approved HTTPS resource sites can open externally. Installation is per-user; stable userData path is independent of app version. Uninstall preserves records.
